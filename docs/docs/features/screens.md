## ログイン画面 `/login`

### 目的

- Tailscale Serve 構成では tailnet 参加端末であることをアクセス境界にするため、通常の利用導線ではログイン画面を使わない。
- 既存ルーティングとの互換や、Cloudflare Access 代替構成を使う場合の案内画面として残す。

### 主な要素

- アプリへ戻る導線
- Cloudflare Access 代替構成を使う場合の認証中表示

### 動作

- Tailscale Serve 構成では、tailnet 外の端末は Hono server に到達しない。
- tailnet 内端末では、`DEV_USER_ID=local-dev-user` の単一ユーザーとしてアプリを利用する。
- Cloudflare Access 代替構成では、未認証の場合に Cloudflare Access の認証ページへリダイレクトされる。
- フロントエンドは JWT を保持しない。

## ダッシュボード `/`

### 目的

- 今日または直近数日の献立や買い物リストへの入口にする。
- よく使う機能へのショートカットをまとめる。

### 主な要素

- 今日の日付と、今日の朝 / 昼 / 夜の献立概要
  - 例: 朝はトースト & サラダ、昼は未設定、夜は鶏の照り焼き
- アクションボタン
  - 「今日の献立を編集」から `/menus` の対象日へ遷移
  - 「今日の買い物リストを見る」から `/shopping-list?from=today&to=today` へ遷移
- レシピ登録ショートカット
  - 「新しいレシピを登録」から `/recipes/new` へ遷移

初期段階では、リンク集と今日の献立概要程度でよい。後から「今週の献立」や「よく作るレシピ」などを追加する。

## レシピ一覧 `/recipes`

### 目的

- 登録済みレシピを一覧表示し、詳細／編集／献立追加へ遷移できるようにする。

### 主な要素

- レシピ一覧テーブルまたはカード
  - レシピ名
  - 出典（本のタイトル＋ページ）
  - 基本人数（`baseServings`）
- 検索・フィルタ
  - レシピ名キーワード検索（まずは部分一致）
  - 出典本での絞り込み（将来対応でもよい）
- アクション
  - 「新規レシピを追加」ボタンから `/recipes/new` へ遷移
  - 各行の「詳細を見る」から `/recipes/:id` へ遷移

## レシピ登録 `/recipes/new`

### 目的

- レシピ本を見ながら、新しいレシピを登録する。

### 主な項目

- レシピ基本情報
  - レシピ名（必須）
  - 出典本のタイトル（任意）
  - 出典ページ番号（任意）
  - 基本人数（例: 2人分）
- 材料一覧
  - 行を追加／削除できる材料リスト
  - 食材名
  - 分量（数値またはテキスト）
  - 単位（g, 個, ml, 大さじ、小さじ、少々など）
  - 備考（「薄切り」「1cm角に切る」など／任意）

### アクション

- 保存時は `POST /recipes` を呼び出す。
- 成功時は作成したレシピの詳細 `/recipes/:id` へ遷移する。
- キャンセル時は `/recipes` へ戻る。

## レシピ詳細／編集 `/recipes/:id`

### 目的

- 登録済みレシピの内容を確認し、必要に応じて編集する。
- 献立に追加する入口にもする。

### 主な要素

- レシピ情報
  - レシピ名
  - 出典本＋ページ
  - 基本人数
- 材料リスト
  - 食材名・分量・単位の一覧
- 編集モード
  - 「編集」ボタンを押すと編集可能にする。
  - 最初から編集モードでもよい。

### アクション

- 編集内容の保存時は `PUT /recipes/:id` を呼び出す。
- 「このレシピを献立に追加」から、日付／食事区分／人数を選択するダイアログまたは別画面へ進む。
- 献立追加時は `POST /menus` を呼び出す。

## 献立一覧／編集 `/menus`

### 目的

- 日付ごとの献立を確認・編集する。
- レシピとの紐付けを行う。

### UI パターン

- まずはシンプルに「日付＋リストビュー」でスタートする。
- 余力があればカレンダー UI に拡張する。

### 主な要素

- 日付単位のリスト
  - 各日付ごとに朝・昼・夜ブロックを表示
  - 各ブロックにレシピ名（複数可）と人数を表示
- フィルタ
  - 表示開始日を選択
  - 表示日数を選択（例: 7日）

### アクション

- 日付ごとの「編集」ボタンで、その日の献立編集モードへ進む。
- 朝 / 昼 / 夜それぞれに「レシピを追加」ボタンを持つ。
- 既存レシピの削除、人数の変更ができる。

### バックエンド連携

- `GET /menus?from=YYYY-MM-DD&to=YYYY-MM-DD`
- `POST /menus`

## 買い物リスト `/shopping-list`

### 目的

- 指定期間の献立から必要な材料の合計量を割り出し、買い物に使えるチェックリストとして表示する。

### 主な要素

- 期間指定フォーム
  - 開始日（from）
  - 終了日（to）
  - 「リストを生成」ボタン
- リスト表示
  - 材料ごとの行を表示する。
  - 例: `[ ] 玉ねぎ …… 1.5個`
  - 常備品を別枠で表示できると理想だが、後回しでもよい。

### アクション

- チェックボックス
  - ユーザー操作のみの一時的なクライアント側状態でもよい。
  - 必要になればローカルストレージに保存する。
- 「条件変更」ボタン
  - 期間を変更して再検索する。

### バックエンド連携

- `GET /shopping-list?from=YYYY-MM-DD&to=YYYY-MM-DD`
- Hono server 側で以下を行う。
  1. 期間内の献立を取得する。
  2. 対象レシピの材料を取得する。
  3. 材料名ごとに合算してレスポンスにまとめる。

## 代表的なユーザーフロー

### レシピ登録

1. `/recipes/new` を開く。
2. レシピ基本情報を入力する。
3. 材料を行追加しながら入力する。
4. 保存して `POST /recipes` を呼び出す。
5. 正常終了後、`/recipes/:id` へ遷移する。

### 献立作成

1. `/recipes` から使いたいレシピの詳細画面を開く。
2. 「このレシピを献立に追加」を押す。
3. 日付、食事区分、人数を指定する。
4. `POST /menus` を呼び出す。
5. `/menus` で当該日付にレシピが反映されていることを確認する。

### 買い物リスト利用

1. スーパーへ行く前に `/shopping-list` を開く。
2. 期間を指定してリストを生成する。
3. 表示されたリストをスマホで確認しながら、買ったものからチェックを入れていく。
4. 買い忘れ防止に利用する。
