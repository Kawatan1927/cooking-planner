## ログイン画面 `/login`

### 目的

- Cloudflare Access による認証を経て、アプリへのアクセスを制御する。
- 認証済みであればダッシュボードへリダイレクトする。

### 動作

- 未認証の場合は Cloudflare Access の認証ページへリダイレクトされる。
- 認証完了後は元の URL へ戻り、アプリを利用できる。
- 認証状態は Cloudflare Access が発行するセッション Cookie で管理する。
- フロントエンドは JWT を保持しない。

## ダッシュボード `/`

- 今日または直近数日の献立を表示する。
- 買い物リストへの導線を表示する。
- レシピ登録や献立編集へのショートカットを表示する。

## レシピ一覧 `/recipes`

- 登録済みレシピを一覧表示する。
- レシピ名で検索できるようにする。
- 詳細画面や新規登録画面へ遷移できるようにする。

## レシピ登録 `/recipes/new`

- レシピ名、出典、基本人数、材料一覧を入力する。
- 保存時は `POST /recipes` を呼び出す。
- 成功時は作成したレシピの詳細へ遷移する。

## レシピ詳細／編集 `/recipes/:id`

- レシピ本体と材料一覧を表示する。
- 編集内容の保存時は `PUT /recipes/:id` を呼び出す。
- 献立に追加する導線を持つ。

## 献立一覧／編集 `/menus`

- 日付ごとの献立を表示する。
- 朝・昼・夜などの食事区分ごとにレシピと人数を管理する。
- `GET /menus?from=YYYY-MM-DD&to=YYYY-MM-DD` で期間内の献立を取得する。
- `POST /menus` で献立を登録する。

## 買い物リスト `/shopping-list`

- 期間指定フォームを表示する。
- `GET /shopping-list?from=YYYY-MM-DD&to=YYYY-MM-DD` を呼び出す。
- Hono server 側で以下を行う。
  1. 期間内の献立を取得する。
  2. 対象レシピの材料を取得する。
  3. 材料名ごとに合算してレスポンスにまとめる。

## 代表的なユーザーフロー

### レシピ登録

1. `/recipes/new` を開く。
2. レシピ基本情報と材料を入力する。
3. 保存して `POST /recipes` を呼び出す。
4. 成功後に `/recipes/:id` へ遷移する。

### 献立作成

1. `/recipes` から使いたいレシピを開く。
2. 献立に追加する。
3. 日付、食事区分、人数を指定する。
4. `/menus` で反映を確認する。

### 買い物リスト利用

1. `/shopping-list` を開く。
2. 期間を指定してリストを生成する。
3. スマホで確認しながら買ったものをチェックする。
