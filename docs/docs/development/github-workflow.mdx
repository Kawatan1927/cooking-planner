## ブランチ戦略

| ブランチ             | 役割                                    |
| -------------------- | --------------------------------------- |
| `main`               | プロダクションブランチ。直接 push 禁止  |
| `develop`            | 将来的に導入する場合の開発統合ブランチ  |
| フィーチャーブランチ | `feature/<Issue番号>-<説明>` 形式で作成 |

Issue から作業ブランチを作成する場合:

```bash
gh issue develop <Issue番号> --name feature/<Issue番号>-<kebab-case-説明> --base main --checkout
```

## Issue / PR の作成ルール

- Issue タイトルは日本語で簡潔に記述する。
- `enhancement`、`bug`、`documentation` など適切なラベルを付ける。
- PR タイトルは対応する Issue と同じにする。
- PR 本文は `.github/PULL_REQUEST_TEMPLATE.md` に従い、`closes #N` を含める。

## コミットメッセージ

```text
docs: 開発手順をバックエンド構成に更新

- backend ディレクトリのセットアップ手順を追加
- 古い実行コマンドを現行スクリプトに置換
```

## CI ワークフロー

GitHub Actions で以下のワークフローが自動実行されます。

### Frontend CI

**トリガー**: `frontend/**` に変更を含む push または PR

| ステップ   | コマンド               |
| ---------- | ---------------------- |
| 型チェック | `bunx tsc -b`          |
| ESLint     | `bun run lint`         |
| Prettier   | `bun run format:check` |
| ビルド     | `bun run build`        |

### Backend CI

**トリガー**: `backend/**` に変更を含む push または PR

| ステップ   | コマンド               |
| ---------- | ---------------------- |
| 型チェック | `bun run type-check`   |
| ESLint     | `bun run lint`         |
| Prettier   | `bun run format:check` |
| テスト     | `bun run test`         |

### Docs CI

**トリガー**: `docs/**` に変更を含む push または PR

| ステップ             | コマンド               |
| -------------------- | ---------------------- |
| フォーマットチェック | `bun run format:check` |
| Docusaurus ビルド    | `bun run build`        |

### Docs Deploy

`main` ブランチへの `docs/**` 変更時、Docusaurus ドキュメントサイトを GitHub Pages へデプロイします。手動実行も可能です。

### Update Docs

AI エージェントがコード差分を分析し、必要なドキュメント更新を検出してドラフト PR を自動生成します。

## ローカル Git フック（lefthook）

`bun install` 時に自動インストールされます。手動インストールは以下です。

```bash
bun run prepare
```

### pre-commit

`frontend/` と `backend/` 配下の staged ファイルに対して並列実行します。

| コマンド名        | 対象                            | 内容              |
| ----------------- | ------------------------------- | ----------------- |
| `frontend-format` | `frontend/**/*.{ts,tsx,...}`    | Prettier チェック |
| `frontend-lint`   | `frontend/**/*.{ts,tsx,js,jsx}` | ESLint            |
| `backend-format`  | `backend/**/*.{ts,js,...}`      | Prettier チェック |
| `backend-lint`    | `backend/**/*.ts`               | ESLint            |

### pre-push

push 対象に `frontend/**` または `backend/**` の変更が含まれる場合のみ実行します。

| コマンド名          | 内容                           |
| ------------------- | ------------------------------ |
| `frontend-build`    | Vite ビルド（`tsc -b` を含む） |
| `backend-typecheck` | 型チェック                     |
| `tests`             | `bun run test`                 |

## プルリクエストのフロー

1. Issue からフィーチャーブランチを作成・チェックアウトする。
2. コードまたはドキュメントを変更する。
3. ローカルで必要な検証を実行する。
4. コミットして push する。
5. PR を作成し、タイトル・ラベル・`closes #N` を記載する。
6. CI のチェック完了を確認する。
7. レビューを受けてマージする。
